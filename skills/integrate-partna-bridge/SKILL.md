# Интеграция partna-bridge

Один источник правды — `llms.txt` в корне репозитория, затем файл нужного уровня в
`docs/integrations/`. Здесь порядок решений и границы.

## Порядок

1. Прочитать `llms.txt`, затем `docs/integrations/README.md` — там таблица «что выбрать».
2. Выбрать минимальный уровень, который закрывает задачу:
   - уровень 1 — владелец заводит партнёров в кабинете, код только на `claim`;
   - уровень 2 — своя регистрация, серверный `claim` и `partner-link`;
   - уровень 3 — своя CRM со связями, факты `member`;
   - уровень 4 — свои экраны, чтение из ядра по ключу тенанта.
3. Открыть файл уровня и следовать ему; не придумывать эндпоинты, которых там нет.
4. Сверить поля с `docs/integrations/fields.md` или `/openapi.json` моста.
5. Прогнать `./scripts/smoke.sh --level N --url … --token … --code … --user …` и показать вывод.

## Границы

- `amount` — всегда минорные единицы: `350000` при `RUB` — это 3 500 ₽.
- `eventId` — устойчивый: повтор с тем же id дубликатом не станет, повтор с новым — станет.
- `order`, `refund`, `member`, `partner-link` — только с `Bearer`-токеном, никогда из браузера.
- `claim` из браузера без токена ограничен 30 запросами в минуту с адреса; серверный вызов — без лимита.
- Ссылка партнёра строится на домене моста (`https://<мост>/r/<code>`); `url` из ядра cookie не ставит.
- Мост не считает комиссии, не делает выплат и не хранит персональные данные. Не обещать обратного.
- Заказ отправляется только по подтверждённой оплате; возврат — после фактического возврата денег.

## Что считать успехом

`/health` отвечает и ключ настроен; `claim` даёт привязку; заказ уходит в очередь (`202`) или
принимается ядром (`200`); в `/v1/outbox` нет записей с ошибкой; `smoke.sh` нужного уровня зелёный.
